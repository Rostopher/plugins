Better Paseo redraws agent conversations as compact rows for tool calls, reasoning, replies, prompts, checklists and errors, and adds an optional Tasks board for every agent on the host. It continues [Beautiful Chat](https://github.com/ABorakati/beautiful-chat), with desktop hover previews, a block details panel, richer selection and copying, and block-by-block streaming Markdown.

Tool calls start collapsed; chosen open and closed states survive completion and remounts. On desktop a click expands a row, and hovering a collapsed row or file path shows a preview that can wrap, number lines, move, resize, maximize or open in a side panel. On touch devices a tap opens the row in a drawer or panel that steps through the turn's blocks, and a long press offers its copy actions. An image viewer provides zoom and pan.

Code, diffs and shell output receive syntax highlighting. Copy text, code, paths, tool results or tables, including a block of cells selected by holding a cell and dragging; desktop table controls also support copying an image. Where a composer is available, selected text can be added to the draft for a later message. Completed replies show copy controls and available model, time and duration information.

The Tasks board lays out every agent of the host in four lanes: needs input, running, to review and done. Cards show the model, thinking level, project, branch, labels, timer and subtasks, and the board can be filtered, sorted and drawn with narrow, default or wide lanes. A click opens a card's properties, token usage, activity and subtasks in a sidebar, a bottom sheet on narrow boards, or a sheet on phones. Cards can stop an agent and answer tool, plan and mode permission requests; questions open the agent's tab.

## Setup and settings

Requires Paseo 0.8 or later; the listing image metadata requires 0.11 or later. No separate service account is needed. Open **Settings → Plugins → Better Paseo** to choose reply styles, spacing, fonts, previews and block details, and to turn on and configure the Tasks board beside a live preview of it. The board is off until turned on. Settings support English and Simplified Chinese and are saved through the daemon. The Git preparation step installs the committed, locked npm dependency tree without development tools.

## Data access and limits

The plugin reads displayed conversation text, tool results and agent metadata. Syntax highlighting sends displayed code to the daemon. Local-image previews read files on the daemon and return image bytes to the connected client; supported images larger than 3 MB are not inlined. File reveal opens the daemon machine's file manager. Selected text added to the composer reaches the selected agent provider when you submit the message.

With Tasks enabled and sidebar counts shown, the sidebar subscribes to agent status and attention on the host. Opening the board, or hovering, focusing or touching its entry, also reads agent details, workspaces, projects, labels and model names. These additional subscriptions can remain active for up to 30 seconds after closing the board. Cards display agent titles, models, working directories, branches, labels, permission requests and token usage.

The plugin server records each turn's start, end, available token usage and, for a turn that failed, its error message per agent in the plugin's data directory on the daemon, including when the Tasks board is disabled. It keeps the latest 500 turn records per agent and saves markers for agents stopped through the board. Stop runs `paseo agent stop` through the host-provided CLI or an installed Paseo CLI found on its command path; without either, the button is hidden. Permission buttons send the same responses as Paseo's own controls.

Presentation and Tasks preferences use daemon settings; presentation preferences also keep a browser cache. The plugin also reads the host's appearance preferences to follow its fonts and theme. The optional `/bc-perf` command enables diagnostic probes; `/bc-perf dump` writes a diagnostic snapshot, including agent identity, timing and client metadata, to the daemon's temporary directory.

Some interactions depend on the host and input device. Permission approvals in the timeline remain owned by Paseo. Turning off plugin Markdown restores Paseo's reply rendering, including Mermaid and its full footer. Large expanded blocks can still be slow on development simulators. Label colours and project icons on the board need a Paseo release that shares them with plugins; until then labels get a neutral dot and projects a letter avatar. The author's [compatibility and benchmark notes](https://github.com/RoundRedDot/better-paseo/blob/b7771d8ad76d2638b23dbe8c76f1dcad10536efb/README.md#compatibility) describe historical test conditions; they do not establish performance for every device or conversation.
